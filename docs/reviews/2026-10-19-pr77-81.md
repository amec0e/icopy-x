## Narrow ICS/iCLASS changes in #80–81

These goals relate to accessory reads/writes, but are independently reviewable
changes. Necessary discovery and startup integration is legitimate accessory
scope. None of these three files changes build scripts or manufacturer branding.

### Success recognition: reject the proposed expression

The new expression at
[`iclasswrite.py:119`](https://github.com/lab-401/icopy-x/blob/63726d4d5d8ac2490241e3f9045398ae851fc59f/src/middleware/iclasswrite.py#L119)
accepts both `Write unsuccessful` and `Write NOT SUCCESSFUL`. If returned in a
command response, either can make `writeDataBlock()` return success. The added
tests cover three other failure strings and miss these counterexamples.

The reported example `Wrote block 6 / 0x06 ( ok )` already matches the old
expression, including when surrounded by spaces: `re.search` does not require
a whole-string match. Factory `Wrote block 07 successful` and the device's
`Wrote block 6/0x06 successful` are normalized in the existing compatibility layer
before middleware parsing. Main has regression tests for these forms. Other
capitalization/spacing variants need real captured evidence and a precise
normalizer/parser test; a broad substring is unsafe. No evidence here proves the
claimed firmware emits every invented variant.

**Value:** robustness against verified output variants is worthwhile; this patch
does not demonstrate the claimed failure and introduces false success. Keep the
current translation boundary. A successful command also does not prove card
readback, which the current ICS write path checks separately.

### Write cleanup: do not transplant global cancellation

The two new `stopPM3Task()` calls occur after a synchronous command returns error
or lacks a success marker
([lines 214–225](https://github.com/lab-401/icopy-x/blob/63726d4d5d8ac2490241e3f9045398ae851fc59f/src/middleware/iclasswrite.py#L214)).
Their tests only count calls to a fake executor; they do not reproduce a timeout,
drain a stale response, reset a co-processor or prove that the next command works.
The fake's default completed return is zero; the real executor returns one.
In that historical executor, normal returns already set `RUNNING=False`;
`stopPM3Task()` only toggles flags/waits and sends no hardware recovery command.
Calling it after such a return does not establish the claimed bus recovery.
The later Astra evaluation also identified a test-isolation defect: reloading
`iclasswrite` binds its module attributes to fake dependencies; restoring only
`sys.modules` afterward does not restore those attributes. The historical UI
conftest does not undo these bindings. Patch the dependency attributes directly
or restore the isolated module explicitly.

The historical executor differs materially from main. Main's #64/#67 changes
retain operation ownership, clear command state in `finally`, bound response
draining and require daemon readiness after uncertain completion. They do not
replay a possibly completed card write. On current main, `stopPM3Task()` cancels
the **current owner**, not a past command identified by the caller. Transplanting
these calls can cancel an enclosing operation, or another owner that starts
after an unreserved command returns. That is a current integration hazard, not
a claim that the historical code already had today's ownership API.

**Value:** investigate a reproducible recovery failure at the transport boundary.
The submitted mock assertions are insufficient; retain main's centralized fixes.

### Discovery: the filter does not provide the claimed isolation

When there are no allowlisted VID/PID matches, the new Linux/macOS condition
`if not dev_ports or c in dev_ports` accepts every globbed serial candidate.
Windows falls back to COM1 through COM256. A controlled Linux probe with only
an unrecognized PM3 device enumerated still opens `/dev/ttyACM0`, flushes its
buffer and writes `Who`. This broad fallback existed before the PR; the patch
fails its stated isolation goal rather than introducing every aspect of it.
If another allowlisted board is present, the same filter can instead hide a
working decoder with different board IDs.

The identity comments are inaccurate: Arduino's board definitions associate
`2341:0043` with Uno, while SparkFun lists `1B4F:9206` for Pro Micro, not Adafruit
Feather. Generic board IDs do not establish that ICS firmware is loaded.
See the manufacturers' [Arduino definitions](https://github.com/arduino/ArduinoCore-avr/blob/master/boards.txt)
and [SparkFun definitions](https://github.com/sparkfun/SF32u4_boards/blob/master/sparkfun/avr/boards.txt).

**Correction to the earlier discussion:** this patch **retains** the Who/ISE
handshake. It does not simply accept a VID/PID as a decoder. Its historical
substring check can accept a response containing `ISE`, however, and the patch
does not change menu visibility. Main now enumerates existing ports, excludes
the reserved PM3 and aliases at enumeration and opening, checks bounded exact
identity, and controls presence/menu updates and serial ownership. Replacing
that implementation with this older function would lose those protections.

**Value:** preventing PM3 interference and showing only a detected accessory are
already implemented on main. Do not replace them with this allowlist. The seven
helper tests never exercise the unsafe fallback or actual discovery.

### Full-field logging: unsupported diagnosis, misleading output

Both the historical base and main preserve the entire response, raw block-7
field and valid normalized 16-hex-character credential. The cited truncating
slice/format is absent from the changed parser. The patch adds a log; it does
not repair such a slice. It logs arbitrary raw text as `Key#` **before** validation:
`Blk7#:not-a-key` produces `Key#: NOT-A-KEY` while the parser correctly refuses
to create a normalized credential. Block-7 credential data should not be
relabelled an authentication key. This also adds persistent credential logging
without establishing a missing diagnostic need.

**Value:** retain exact raw export and normalization. Ask for a precise failing
screen/log and firmware version before changing diagnostics. Five logging tests
mostly demand the new output, including a deliberately overlong raw value;
they do not demonstrate an old truncation failure.

## Evidence, limits and next action

- Compared all five immutable trees, including renames, encoded source and
  historical/current callers. Re-read issues #58–61 and the maintainer's
  [#81 explanation](https://github.com/lab-401/icopy-x/pull/81#issuecomment-6270749369).
- AST parsing and strict base64 decoding established submission integrity.
  Controlled functions with inert serial/time/log dependencies reproduced regex
  false success, PM3 fallback probing, 256 guessed Windows ports, and unchanged
  full block-7 preservation before/after. These are source counterexamples, not
  assertions that those exact messages were observed on hardware.
- On main, **466 relevant host tests passed**: ICS transport/presence/activity,
  response compatibility, PM3 ownership/recovery, read/scan safety and IPK input
  contracts. Local Python was 3.14.6; the merged #102 CI separately passed the
  supported host matrix, package builds and 23 QEMU cases for each package.
- Did not import candidate modules, run submitted binaries or flash a device.
  No ICS accessory was available. No genuine ICS USB/RF/write behavior is
  certified by this audit or by mocked/QEMU tests.
- Automatic-review preparation rejects the full #77–79 tree at its changed-path
  limit before any API call (renames count as old and new paths in the collector).
  That is an explicit coverage refusal, not a model review. The narrow #80–81
  historical case is prepared separately with its actual executor/compatibility
  context and predeclared expectations. Do not pay to review duplicate trees.

Keep these PRs closed. Retain the existing main fixes. If maintainers want the
iCLASS dictionary feature, open one focused proposal with traceable key sources,
bounded/deduplicated searches, preserved fallback behavior, storage-failure and
cancellation tests, and explicit physical coverage gaps. Credit Dysonian-Lab's
idea in source/GitHub when implementing it. No candidate runtime code was adopted
by this documentation change.

The subsequent [Astra evaluation](../../tools/auto_review/calibration/20261019-closed-prs/results.json)
returned all three validated passes for the narrow tree, with useful findings
and explicit missing-context limitations. Its incomplete coverage declaration
is not a timeout or proof that the unchanged recovery/localization paths passed.
